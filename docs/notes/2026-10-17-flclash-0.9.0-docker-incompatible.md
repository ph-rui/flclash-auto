# FlClash 0.9.0 在 headless Docker 镜像里不会启动核心

- **日期**：2026-10-17
- **环境**：本仓库用户的 `flclash:0.8.98` 镜像（Debian + cinit/supervisor + Xvnc，应用以 uid 1000 运行，`--privileged` + `/dev/net/tun`）
- **上游 issue**：https://github.com/chen08209/FlClash/issues/2728
- **结论**：0.9.0 的 app 能启动、能读配置、能算出出口 IP，但**始终没有拉起 `FlClashCore`**，因此 7890 不监听、代理不可用。等待 8 分钟无变化，不是"启动慢"。

## 现象

从 0.8.98 升级到 0.9.0 后：

```
[app] [APP] init result: true
[app] [APP] setup ===> <profile>
[app] [APP] checkIp res: ... ip: <出口 IP>, countryCode: HK   # 这一瞬间还是旧核心在跑
[app] [APP] IPC Disconnected
[app] [APP] message: core done
```

之后 app 进程常驻，但没有 `FlClashCore` 子进程：

```
$ ps -ef | grep FlClash
app   909   1  0 14:36 pts/7  00:00:02 FlClash
# 0.8.98 正常时是：
app   913   1 34 14:36 pts/7  00:02:20 FlClash
app   989 913  0 14:36 pts/7  00:00:00 /opt/FlClash/FlClashCore /tmp/FlClashSocket_4786.sock
```

## 证据

0.9.0 的 npm 包级 breaking change 写着：

- `core,helper`：**The elevated Core only answers its owner**
- 新增 `FlClashHelperService`（1.4 MB），由它启动核心

在本镜像里手动启动 helper 会直接退出，并缺少环境变量：

```
$ /opt/FlClash/FlClashHelperService
Error: FLCLASH_HELPER_OWNER_UID is not set

$ FLCLASH_HELPER_OWNER_UID=1000 /opt/FlClash/FlClashHelperService
Error: FLCLASH_HELPER_OWNER_GID is not set
```

补齐两个变量后 helper 仍不驻留（无输出、进程消失），说明它还需要本镜像里没有的宿主侧条件（如 root 启动 + 系统总线/polkit 协商）。应用以 uid 1000 运行，无法自行提权拉起 helper，于是核心永远不启动。

## 复现

```bash
# 复制一份生产数据，在独立网络命名空间里跑，不影响线上
cp -a ~/flclash-docker/flclash/. /tmp/t0900/data/
docker run -d --name flclash-t0900 --user 0:0 --privileged --cap-add NET_ADMIN \
  --device /dev/net/tun -v /tmp/t0900/data:/config/xdg/data/com.follow.clash \
  -p 27890:7890 flclash:0.8.98

# 基线：0.8.98 经 27890 出网正常（约 9 秒）
# 装 0.9.0 并重启
docker cp FlClash-0.9.0-linux-amd64.deb flclash-t0900:/tmp/f.deb
docker exec flclash-t0900 pkill -f '/opt/FlClash/FlClash'; sleep 3
docker exec flclash-t0900 dpkg -i /tmp/f.deb
docker restart flclash-t0900

# 观察 8 分钟：27890 始终无响应，7890 不监听，无 FlClashCore 进程
```

## 影响与当前处理

- `flclash-auto` 的行为是正确的：健康检查失败 → 标记 `0.9.0` 为坏版本 → 回滚 → 不再自动尝试该版本（0.9.1 起会重新走 7 天观察）。
- **回滚必须连数据库一起还原**：0.9.0 会把 `database.sqlite` 迁移成新 schema（45 KB → 69 KB），只换回旧镜像会让 0.8.98 读不了新库。本仓库的 `do_rollback` 已修复为"先还原升级前的 `database.sqlite` / `shared_preferences.json`，再换镜像"。

## 后续可尝试的方向（未验证）

1. 让 app 以 root 运行（去掉 cinit 的 `--default-service-uid 1000`），看能否拉起 helper。
2. 在镜像里由 supervisor 以 root 常驻 `FlClashHelperService`，并注入 `FLCLASH_HELPER_OWNER_UID/GID`。
3. 等上游 0.9.1+ 修复 headless 场景（若 0.9.x 持续不可用，可将 `UPGRADE_ENABLED=0` 或保持坏版本拉黑）。
